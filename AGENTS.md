# Agents Guide

Two packages for Roslyn source generators which copy a method into a file of its own and change it on the way.

- `Zomp.MethodCloning` (`src/Zomp.MethodCloning`) is the core: finding the marked methods, collecting what a copy needs to compile elsewhere, fully qualifying names, naming the files and registering the output. It ships as **source**, compiled into each generator which references it.
- `Zomp.MethodCloning.Variants` (`src/Zomp.MethodCloning.Variants`) is a ready generator built on the core: `[CloneVariants("Bmp", "Gif", "Png")]` writes the `Gif` and `Png` variants of a method written for `Bmp`. It replaces T4 templates which stamp out the same method once per type.

The core came out of [Zomp.SyncMethodGenerator](https://github.com/zompinc/sync-method-generator), which is its other consumer.

## Documentation

The package READMEs are what nuget.org shows, so they stay short: what the package is, an example, how to install it, and the rules at a glance. Reference material goes in `docs/`, linked from the READMEs by absolute GitHub URL, since relative links break on nuget.org.

## Build & Test

```bash
dotnet build
dotnet test
```

Tests use TUnit on Microsoft.Testing.Platform (`global.json` opts in) with Verify snapshots. A new or changed snapshot is written as `.received.txt`; review it, then rename it to `.verified.txt`.

- `tests/Zomp.MethodCloning.Testing` compiles the core sources against Roslyn 5.0 with every `ROSLYN_*` constant defined, and adds an identity generator: `[Cloning.Clone]` copies a method and changes nothing but its name, appending `Clone`. Its output is what the core does on its own.
- `tests/Zomp.MethodCloning.Tests/Cloning` tests the core through the identity generator: qualification, file names, containing types, nullability, preprocessor directives, extension blocks and incremental caching. Snapshots are in `Cloning/Snapshots`. Each clone has to compile without errors, and without broken `cref`s.
- The rest of `tests/Zomp.MethodCloning.Tests` tests the Variants generator, with snapshots in `Snapshots`.

A cloning bug gets its failing test and its fix here, as an identity test, whichever consumer it was found through. Zomp.SyncMethodGenerator adds a test of its own only when the bug shows up through its async-to-sync rewriting.

Verify 33 adds a SponsorCheck gate which fails the build until a sponsorship or licence property is set. This repository claims Verify's `OpenSource` exemption, for open source projects which generate no revenue, in `Directory.Build.props`. The claim expires at the month in `Verify_SponsorshipExemptionUntil`, at most 12 months out, and has to be renewed by moving that month forward.

## Rules for the core sources

The files in `src/Zomp.MethodCloning` compile inside other people's projects, which changes what they may assume.

- **Explicit usings in every file.** Implicit and global usings are off in the projects which compile these files, because the consumer's global usings are unknown. This is a deliberate exception to the Zomp convention of no file-level usings.
- **Every file starts with `// <auto-generated/>` and `#nullable enable`.** The marker makes the consumer's analyzers skip the files, since the consumer's `.editorconfig` does not reach `~/.nuget/packages`. Here `.editorconfig` sets `generated_code = false` for them, so they are still analyzed in this repo. Generated code defaults to nullable disabled, hence the directive.
- **Both sides of every `#if ROSLYN_*` guard must compile.** The core project compiles against Roslyn 5.0 with all the constants defined; the Variants project compiles the same files against Roslyn 4.8 with none. A build of the solution exercises both. Collection expressions for `ImmutableArray` need `ROSLYN_4_12_OR_GREATER`, since the `System.Collections.Immutable` which Roslyn 4.8 brings predates them.
- **Internal types, no dependencies** beyond Roslyn itself. Consumers on `netstandard2.0` need the polyfills the files use (`IsExternalInit`, `NotNullWhenAttribute` and the like), which PolySharp provides.

## Variants diagnostics

| ID     | Severity | Meaning                                                     |
| ------ | -------- | ----------------------------------------------------------- |
| ZMC001 | Error    | Two variants would declare the same member                  |
| ZMC002 | Error    | The method's name does not contain the word being swapped   |
| ZMC003 | Warning  | A type named after the original has no counterpart, so kept |

A new descriptor must also be listed in `src/Zomp.MethodCloning.Variants/AnalyzerReleases.Unshipped.md`, or `RS2008` fails the build.

## Packing

```bash
dotnet pack -c Release -o <feed>
```

Until the packages are on a public feed, consumers restore them from a local folder feed, `~/.nuget/local-feed`, mapped in their `nuget.config`. A branch which depends on it cannot pass CI.

## Conventions

- Default branch `master`; topic branches and PRs for anything reviewable.
- CRLF line endings, enforced by `.editorconfig`.
- Versions come from git through Nerdbank.GitVersioning (`version.json`).
